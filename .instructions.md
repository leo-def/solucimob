# Development Instructions for AI Agents - Solucimob

> Guidelines for AI-assisted Docker Compose orchestration and service coordination.

## 🎯 Project Overview

- **Purpose**: Orchestrate multiple microservices and infrastructure
- **Type**: Docker Compose orchestrator
- **Tech Stack**: Docker Compose, Nginx, Node.js services, MongoDB Atlas
- **Deployment**: Containerized multi-service coordination

---

## 🏗 Architecture Pattern

**Microservices Orchestration**:
- Central docker-compose.yml coordinates all services
- Nginx acts as API gateway/load balancer
- Services communicate via internal Docker network
- Environment variables control configuration

### Key Components
```
docker-compose.yml   - Service definitions and configuration
nginx.conf          - Load balancer routing rules
.env               - Environment variables (secrets)
Services           - solucimob-calc, solucimob-config
```

---

## 📂 File Naming & Conventions

**Docker Compose Files**:
- `docker-compose.yml`: Base configuration
- `docker-compose.prod.yml`: Production overrides
- `docker-compose.staging.yml`: Staging overrides

**Configuration Files**:
- `nginx.conf`: Nginx load balancer configuration
- `.env`: Environment variables (not committed)
- `.env.example`: Template with non-sensitive defaults

**Service References**: lowercase with hyphens
- `solucimob-calc`, `solucimob-config`, `mongo-db`

---

## ✅ DO's

1. **DO** use `.env.example` as template committed to git
2. **DO** define service dependencies explicitly
3. **DO** implement health checks for each service
4. **DO** use Docker networks for service communication
5. **DO** document all environment variables needed

---

## ❌ DON'Ts

1. **DON'T** commit `.env` with actual secrets
2. **DON'T** hardcode service URLs (use environment variables)
3. **DON'T** skip health checks
4. **DON'T** use `localhost` for inter-service communication (use service name)
5. **DON'T** expose services without Nginx gateway

---

## 📋 Common Workflows

**Starting the orchestrator**:
```bash
cp .env.example .env
# Edit .env with actual values
docker-compose up --build
# Services available at http://localhost:8080
```

**Adding a new service**:
1. Update `docker-compose.yml` with service definition
2. Add environment variables to `.env.example` and `.env`
3. Update `nginx.conf` with new route
4. Add health check endpoint
5. Test with `docker-compose up`

**Debugging service communication**:
1. Check service logs: `docker-compose logs service-name`
2. Verify DNS resolution: `docker-compose exec service-name nslookup other-service`
3. Check network: `docker network inspect solucimob_default`
4. Verify ports and configuration

**Environment management**:
1. Create `.env` from `.env.example`
2. Set required variables (DATABASE_URL, NODE_ENV, etc.)
3. For production: Use secrets manager (AWS Secrets, Azure Key Vault)
4. Never commit `.env` to version control

**Health checks**:
```yaml
healthcheck:
  test: ["CMD", "curl", "-f", "http://localhost:3001/health"]
  interval: 30s
  timeout: 10s
  retries: 3
  start_period: 40s
```
